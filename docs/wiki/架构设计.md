## 核心模块

### main.py - 入口调度

- 解析命令行参数
- 启动 GUI 或 CLI 模式
- 传递参数到数据流水线

### gui_app.py - 图形界面

- Tkinter GUI 实现
- 分页显示数据（每页200行）
- 进度条和日志输出
- 参数设置对话框
- 双击打开同花顺个股页面

### data_collector.py - 数据流水线

5阶段流水线设计：

1. **Stage 1 - 股票清单**：获取全部A股代码（~5500只）
2. **Stage 2 - 实时行情**：批量拉取实时报价、涨跌幅、成交量等
3. **Stage 2.5 - 预过滤**：剔除ST、退市、市值<80亿
4. **Stage 3 - 历史K线**：增量拉取日K线数据（开高低收量）
5. **Stage 4 - 指标计算**：MA/KDJ/MACD/换手率极值等
6. **Stage 5 - 筛选导出**：应用筛选策略，导出Excel

### cache.py - 缓存管理

三级缓存策略：

| 缓存类型 | 后端 | 用途 | 更新策略 |
|---------|------|------|---------|
| 股票清单 | JSON | 避免重复获取代码列表 | 7天TTL |
| 实时行情 | Parquet | 按日期存储每日行情 | 每日新文件 |
| 历史K线 | SQLite | 存储日K线数据 | 增量追加 |
| 总股本 | SQLite | 计算换手率 | 按需更新 |

### data_exporter.py - 筛选导出

- 5种筛选策略实现
- Excel导出（xlsxwriter格式化）
- 数据展示转换（合并列、布尔值映射）

## 数据流

```
用户启动
    ↓
[Stage 1] 获取股票清单 ──► stock_list.json (缓存7天)
    ↓
[Stage 2] 批量拉取实时行情 ──► realtime_YYYYMMDD.parquet
    ↓
[Stage 2.5] 过滤 ST/退市/市值<80亿
    ↓
[Stage 3] 增量拉取历史K线 ──► history.db (SQLite)
    │   ├─ 检查缓存最新日期
    │   ├─ 计算需要拉取的日期范围
    │   ├─ 批量并发拉取（4 workers）
    │   └─ 追加到SQLite（INSERT OR IGNORE）
    ↓
[Stage 3.5] 滚动缓存清理 ──► 每只股票保留最近200根K线
    ↓
[Stage 4] 从缓存加载完整K线，计算指标
    │   ├─ MA5/20/60/120 均价
    │   ├─ 5/30日平均成交量
    │   ├─ 5/10/20/30/60日换手率极值
    │   ├─ KDJ/MACD 金叉信号
    │   └─ 总股本缓存（用于换手率计算）
    ↓
[Stage 5] 应用筛选策略 ──► Excel导出
    ↓
完成
```

## 关键设计决策

### 1. 为什么用腾讯API而不是akshare？

- akshare 的 K 线接口底层也是调用第三方 API，有额外开销
- 直接 HTTP 调用快 20 倍（0.1s vs 2s per stock）
- 批量请求更灵活，可控并发和延迟

### 2. 为什么用增量更新？

- 首次运行拉取 168 天数据（~5分钟）
- 后续运行只拉取新增日期（~1分钟）
- 90%+ 减少每日数据拉取量

### 3. 为什么 Stage 4 从缓存加载？

- 增量拉取只返回新数据（可能只有1根K线）
- MA 计算需要完整历史（至少120根）
- 缓存已包含历史+新数据，直接加载最高效

### 4. 为什么滚动清理缓存？

- 防止 SQLite 无限增长
- 保留最近 200 根 K 线（足够 MA120 计算）
- 自动删除陈旧数据，保持缓存精简

### 5. 为什么指数行不在GUI显示？

- 指数数据用于筛选基准比对（如"跑赢沪深300"）
- 但指数的市盈率、市值等字段无意义（设为None）
- 显示会造成混淆，隐藏但保留计算用途

## 性能优化

| 优化项 | 效果 |
|-------|------|
| 腾讯HTTP直连 | 比akshare快20倍 |
| 批量并发（4 workers） | 减少网络等待 |
| 增量更新 | 90%+减少拉取量 |
| 滚动缓存清理 | 控制数据库大小 |
| 缓存总股本 | 避免重复计算换手率 |

## 错误处理

- **重试机制**：K线拉取失败自动重试3次（tenacity）
- **频率限制**：批量请求间加0.1秒延迟
- **数据回退**：实时数据缺失时从K线补充
- **优雅降级**：部分股票拉取失败不影响整体
