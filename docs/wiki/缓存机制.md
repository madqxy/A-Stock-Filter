# 缓存机制

## 概述

系统采用三级缓存策略，大幅减少网络请求，提升运行速度。

## 缓存架构

```
┌─────────────────────────────────────────────────────────┐
│                    三级缓存体系                          │
├─────────────────────────────────────────────────────────┤
│  Level 1: JSON 缓存                                     │
│  ├─ 数据: 股票清单 (stock_list.json)                    │
│  ├─ TTL: 7天                                            │
│  └─ 用途: 避免重复获取5500+只股票代码                    │
├─────────────────────────────────────────────────────────┤
│  Level 2: Parquet 缓存                                  │
│  ├─ 数据: 实时行情 (realtime_YYYYMMDD.parquet)          │
│  ├─ 命名: 按日期分文件                                   │
│  └─ 用途: 避免盘中重复拉取实时数据                        │
├─────────────────────────────────────────────────────────┤
│  Level 3: SQLite 缓存                                   │
│  ├─ 数据: 历史K线 (history.db)                          │
│  ├─ 策略: 增量追加 + 滚动清理                            │
│  └─ 用途: 存储日K线数据，支持增量更新                     │
└─────────────────────────────────────────────────────────┘
```

## Level 1: JSON 缓存

### 股票清单缓存

**文件**: `data_cache/data/stock_list.json`

**内容**:
```json
{
  "updated_at": "2026-07-01T09:30:00",
  "codes": ["000001", "000002", "600000", ...]
}
```

**TTL**: 7天

**逻辑**:
```python
if cache.is_stock_list_fresh():
    codes = cache.load_stock_list()
else:
    codes = get_stock_list()  # 从 akshare 获取
    cache.save_stock_list(codes)
```

**用途**: 避免每次运行都调用 `ak.stock_info_a_code_name()` 获取5500+只股票代码。

## Level 2: Parquet 缓存

### 实时行情缓存

**文件**: `data_cache/data/realtime_YYYYMMDD.parquet`

**命名规则**: 按日期分文件，如 `realtime_20260701.parquet`

**内容**: DataFrame 格式，包含全部股票的实时行情数据

**新鲜度判断**:
```python
def is_realtime_fresh():
    if not cache_file.exists():
        return False
    mtime = cache_file.mtime()
    if mtime.date() != today:
        return False
    if market_is_open():
        return True  # 盘中使用缓存
    else:
        # 盘后：只有在15:05后保存的缓存才有效
        return mtime.hour > 15 or (mtime.hour == 15 and mtime.minute >= 5)
```

**设计考虑**:
- 盘中（9:30-15:00）：使用缓存，避免重复拉取
- 盘后（15:00后）：如果缓存是在盘中保存的，重新拉取收盘价
- 15:05后保存的缓存：视为有效（已包含收盘数据）

**用途**: 避免盘中重复拉取实时行情，同时确保盘后使用准确的收盘数据。

## Level 3: SQLite 缓存

### 历史K线缓存

**文件**: `data_cache/data/history.db`

**表结构**:
```sql
CREATE TABLE kline (
    code TEXT,
    date TEXT,
    open REAL,
    close REAL,
    high REAL,
    low REAL,
    volume REAL,
    PRIMARY KEY (code, date)
);
```

**增量更新逻辑**:
```
1. 查询每只股票的缓存最新日期: MAX(date) GROUP BY code
2. 计算需要拉取的起始日期: max(缓存最新日期+1, 计算的最新交易日)
3. 只拉取新增日期的K线数据
4. INSERT OR IGNORE 追加到 SQLite（自动去重）
```

**示例**:
```
缓存最新日期: 2026-06-30
计算最新交易日: 2026-07-01
需要拉取: 2026-07-01 的K线

如果 2026-07-01 是交易日:
  → 拉取 2026-07-01 的数据
  → INSERT OR IGNORE 追加到缓存

如果 2026-07-01 不是交易日:
  → API 返回空数据
  → 缓存不变
```

**滚动清理**:
```python
def trim_kline(keep_bars=200):
    """每只股票保留最近200根K线，删除陈旧数据"""
    for code in all_codes:
        DELETE FROM kline 
        WHERE code = ? AND date NOT IN (
            SELECT date FROM kline 
            WHERE code = ? 
            ORDER BY date DESC 
            LIMIT 200
        )
```

**设计考虑**:
- 增量更新：只拉取新增数据，节省90%+网络流量
- INSERT OR IGNORE：自动去重，无需手动检查
- 滚动清理：防止数据库无限增长，保留200根K线足够MA120计算

### 总股本缓存

**表**: `stock_info`

**结构**:
```sql
CREATE TABLE stock_info (
    code TEXT PRIMARY KEY,
    total_shares REAL,
    updated_at TEXT
);
```

**用途**: 计算换手率

**逻辑**:
```python
# 优先使用缓存的总股本
total_shares = cache.get_total_shares(code)

# 如果缓存没有，从实时数据计算
if total_shares is None:
    total_shares = volume / (turnover_rate / 100)
    cache.save_total_shares(code, total_shares)
```

**设计考虑**:
- 实时数据的换手率可能缺失（非交易时间）
- 缓存总股本确保换手率计算可靠
- 总股本变化频率低（除增发/回购外），缓存有效

## 缓存一致性

### 问题场景

**场景1**: 盘中保存的缓存，盘后使用

**解决**: `is_realtime_fresh()` 检查缓存保存时间
- 如果缓存是在15:05前保存的，盘后重新拉取
- 如果缓存是在15:05后保存的，视为有效（已包含收盘数据）

**场景2**: 节假日后运行，缓存日期不是交易日

**解决**: `effective_latest = max(计算最新, 缓存最新)`
- 计算最新交易日（考虑周末）
- 如果缓存日期 > 计算日期（如节假日调休），使用缓存日期
- 避免重复拉取已缓存的数据

**场景3**: 增量拉取只返回1根K线，MA计算需要120根

**解决**: Stage 4 从缓存加载完整数据
- 增量拉取只获取新数据（可能只有1根）
- INSERT OR IGNORE 追加到缓存
- Stage 4 从缓存加载完整历史（包含旧数据+新数据）
- MA计算使用完整历史数据

## 缓存技术细节

### JSON 缓存

- 使用 Python 标准 `json` 库
- 支持 TTL（Time To Live）检查
- 文件锁防止并发写入

### Parquet 缓存

- 使用 `pyarrow` 引擎
- 列式存储，压缩率高
- 支持快速读取和过滤

### SQLite 缓存

- 使用 Python 标准 `sqlite3` 库
- 主键索引：`(code, date)`
- 支持事务和并发控制
- INSERT OR IGNORE 自动去重
- 支持增量追加和滚动清理
